# 画布系统 ↔ 产品工厂 双向同步验证操作清单

> 生成日期：2026-08-29
> 适用范围：canvas-service 的双向同步模块（交付物二）
> 前置条件：首期全量同步（sync/SyncTool.java）已完成，本机 core_db 已有 7111 画面 / 203625 元件数据

---

## 0. 关键配置与开关

| 配置项 | 文件 | 当前值 | 说明 |
|---|---|---|---|
| `canvas.sync.enabled` | canvas-app/.../application.properties | `false` | **总开关**，false=不执行任何同步 |
| `canvas.sync.pull-interval-ms` | 同上 | `300000` | 定时 PULL 间隔（毫秒，默认 5 分钟） |
| `hs.datasource.prod.url` | canvas-app/.../middleware.properties | `10.1.23.21:33061/fpic_prod_db` | 产品工厂源库 |
| `hs.datasource.prod.username` | 同上 | `fpic_prod` | 可写账号 |
| `hs.datasource.prod.password` | 同上 | `123456` | 生产环境应替换为加密值 |

**两个方向：**
- **PULL**（产品工厂 → 画布）：定时任务按 `d_uptr_time` 增量拉取，写入画布表。
- **PUSH**（画布 → 产品工厂）：`saveCanvas / deleteCanvas / updateCanvasJson / copyCanvas` 被调用后自动回写源库。

---

## 1. 启用开关（首次启用前必读）

### 1.1 建立同步基线（重要，避免首次 PULL 全量）

PULL 增量依赖 `tb_canvas_sync_log` 里最近一次 SUCCESS 的时间戳。若该表为空，首次 PULL 会按 `since=1970` 全量拉取，对 20 万元件重复 upsert（幂等但耗时约数分钟）。

首期全量已由 SyncTool 完成，因此启用开关前，**先插入一条基线日志**，把增量起点设为当前时间：

```sql
-- 本机画布库
USE core_db;
INSERT INTO tb_canvas_sync_log
(c_pk_id, c_direction, c_table_name, n_row_count, d_start_time, d_end_time, c_status, c_message, d_crtr_time)
VALUES
(CONCAT('BASE', UNIX_TIMESTAMP(NOW())), 'PULL', 'baseline', 0, NOW(), NOW(), 'SUCCESS', 'SyncTool 全量基线', NOW());
```

> 注意：`lastSyncTime()` 取的是 PULL 方向 SUCCESS 记录的最大 `d_end_time`，所以这条基线记录会把增量起点推进到「现在」。

### 1.2 改开关并重启

编辑 `application.properties`：
```properties
canvas.sync.enabled=true
```
重启 canvas-service 使开关生效。

### 1.3 验证开关已生效

启动日志中，定时任务首轮执行时若日志级别为 DEBUG 不会打印跳过信息；可直接看 `tb_canvas_sync_log` 是否有新记录，或临时把 `ProdCanvasSyncServiceImpl` 的 `log.debug` 观察改为 `log.info`。

## 2. 验证 PULL（产品工厂 → 画布）

目标：产品工厂改了某画面/元件后，画布系统在下一个定时周期（默认 5 分钟）内同步到。

### 步骤

1. 在**源库**选一个已同步的画面，记下其 `c_screen_no` 和某元件 `c_elem_no`：
```sql
-- 源库 fpic_prod_db
SELECT c_screen_no, c_elem_no, c_elem_cname, d_uptr_time
FROM tb_prod_screen_rel_elem LIMIT 1;
```
假设得到 `c_screen_no='135618'`、`c_elem_no='E01859'`、`c_elem_cname='证件有效起期'`。

2. 在源库改这条元件的名称（生产库写操作，务必谨慎，改完可立即改回）：
```sql
UPDATE tb_prod_screen_rel_elem
SET c_elem_cname = '证件有效起期-同步测试', d_uptr_time = NOW()
WHERE c_screen_no = '135618' AND c_elem_no = 'E01859';
```

3. 等待一个定时周期（默认 5 分钟，或临时把 `pull-interval-ms` 调小如 `30000` 后重启），或手动触发：调用 `ProdCanvasSyncServiceImpl.pullIncremental()`（如有测试入口/接口）。

4. 查画布库确认已同步：
```sql
-- 本机 core_db
SELECT c_elem_name, d_uptr_time
FROM tb_canvas_element
WHERE c_canvas_code = '135618' AND c_elem_code = 'E01859';
```
预期 `c_elem_name` 变为 `证件有效起期-同步测试`。

5. 查同步日志：
```sql
SELECT c_direction, c_table_name, n_row_count, c_status, c_message, d_start_time, d_end_time
FROM tb_canvas_sync_log ORDER BY d_end_time DESC LIMIT 10;
```
预期出现 `PULL / tb_canvas_element / 1 / SUCCESS`。

6. **恢复源库数据**（把测试改动改回）：
```sql
UPDATE tb_prod_screen_rel_elem
SET c_elem_cname = '证件有效起期', d_uptr_time = NOW()
WHERE c_screen_no = '135618' AND c_elem_no = 'E01859';
```

> 说明：PULL 使用 `INSERT ... ON DUPLICATE KEY UPDATE`，依赖 `tb_canvas_element` 的 `uk_canvas_elem(c_canvas_code, c_elem_code)` 唯一键（已建）。

## 3. 验证 PUSH（画布 → 产品工厂）

目标：在画布系统保存/调整画布后，产品工厂对应画面同步更新。

### 3.1 前提约束

- PUSH 只能**更新已存在的画面**。产品工厂 `tb_prod_rel_screen` 有外键（依赖 `c_prod_no`/`c_version`），画布系统**新建**的画面因无产品/版本上下文会被跳过（日志提示）。
- 因此验证 PUSH 必须选一个**已在产品工厂存在**的画面（即首期同步来的 7111 个之一）。

### 步骤

1. 选一个已同步画面，记录其源库名称：
```sql
-- 源库
SELECT c_screen_no, c_screen_cname FROM tb_prod_rel_screen LIMIT 1;
```
假设 `c_screen_no='135618'`、`c_screen_cname='某画面名'`。

2. 通过画布系统接口调用 `saveCanvas` 或 `updateCanvasJson`，修改该画布的名称/JSON（等价于调整画布）。示例（`updateCanvasJson` 会重解析 JSON 并重建 element/config，PUSH 更彻底）：
   - 调 `updateCanvasJson`，`canvasCode=135618`，`canvasJson` 为修改后的 JSON。

3. 查源库确认已回写：
```sql
SELECT c_screen_cname, c_screen_ename, d_uptr_time
FROM tb_prod_rel_screen WHERE c_screen_no = '135618';
```
预期名称更新、`d_uptr_time` 刷新。

4. 查同步日志：
```sql
SELECT * FROM tb_canvas_sync_log WHERE c_direction='PUSH' ORDER BY d_end_time DESC LIMIT 10;
```
预期出现 `PUSH / tb_prod_rel_screen / 1 / SUCCESS`、`PUSH / tb_prod_screen_rel_elem / N / SUCCESS`、`PUSH / tb_prod_screen_prop / 1 / SUCCESS`。

### 3.2 注意：PUSH 元件的 upsert 键

PUSH 元件按 `(c_screen_no, c_elem_no)` 匹配更新。若画布系统里某元件在源库不存在，且有画面上下文（`c_prod_no/c_version/c_chnl_code`），会以雪花 ID 新增；无上下文则跳过。

## 4. 验证删除回写（PUSH 删除）

目标：画布系统删除画布后，产品工厂对应画面被删除。

### 步骤

1. 选一个已同步画面（建议用测试画面，勿删生产关键画面）。
2. 调用 `deleteCanvas`，`canvasCode=该画面`。
3. 查源库：
```sql
SELECT COUNT(*) FROM tb_prod_rel_screen WHERE c_screen_no = '135618';
SELECT COUNT(*) FROM tb_prod_screen_rel_elem WHERE c_screen_no = '135618';
SELECT COUNT(*) FROM tb_prod_screen_prop WHERE c_screen_no = '135618';
```
预期均为 0（按元件→属性→画面的顺序删除，符合外键约束）。

> ⚠️ 删除是**不可逆**的生产库写操作，验证务必用无业务影响的画面。

## 5. 边界与冲突策略

| 场景 | 行为 |
|---|---|
| 开关关闭 | PULL 定时任务、PUSH 回写/删除全部空操作（不碰源库） |
| 画布新建画面 | PUSH 跳过（无 `c_prod_no/c_version` 上下文），记日志 |
| 源库同 `c_screen_no` 无记录 | PUSH 跳过，记日志 |
| 首期同步后再 PULL | 需先插基线记录（见 1.1），否则全量重放 |
| 冲突（源与画布同时改） | 当前为「后写覆盖」，未做 `d_uptr_time` 比较仲裁。若要仲裁需在实现里补比较逻辑 |

---

## 6. 关闭/回滚

- 关闭同步：`canvas.sync.enabled=false`，重启。
- 完全还原画布数据：重跑 `sync/SyncTool.java`（会先清空 8 张表再全量同步）。
- 移除同步模块的 schema：`ALTER TABLE tb_canvas_element DROP INDEX uk_canvas_elem;` + `DROP TABLE tb_canvas_sync_log;`（仅当不再需要双向同步时）。

## 7. 一键验证脚本（可选）

将上述 PULL 验证的 SQL 与等待打包成脚本，可复用 `sync/` 目录下已编译的 mysql 连接方式。核心命令：

```bash
MYSQL="C:/Program Files (x86)/MySQL/MySQL Server 5.5/bin/mysql.exe"

# 源库（产品工厂）
$MYSQL -h10.1.23.21 -P33061 -ufpic_prod -p123456 fpic_prod_db -e "UPDATE tb_prod_screen_rel_elem SET c_elem_cname='证件有效起期-同步测试', d_uptr_time=NOW() WHERE c_screen_no='135618' AND c_elem_no='E01859';"

# 等待一个定时周期后查画布库
$MYSQL -hlocalhost -P3306 -uroot -p123456 core_db -e "SELECT c_elem_name FROM tb_canvas_element WHERE c_canvas_code='135618' AND c_elem_code='E01859';"
```

> 生产库写操作务必谨慎：PUSH 回写默认关闭；验证删除/更新时选无业务影响的数据，完成后立即恢复。
