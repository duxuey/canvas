# 反向同步方案：画布系统 → 产品工厂

> 生成日期：2026-08-30
> 前提：三层模型同步已落地（元件定义 / 组件 / 画布），画布系统已具备页面级按钮编辑能力。

---

## 一、反向同步的总体架构

### 三层映射（画布 → 产品工厂）

| 画布系统 | 产品工厂 | 反向动作 |
|---|---|---|
| 画布 `tb_canvas`（`c_canvas_code = 产品号_contentType`） | 产品页面 = 该产品该类型的 screen 集合 | 画布 items 决定 screen 的增删顺序 |
| 组件 `tb_element_group`（`c_group_code = c_screen_no`，`c_group_tag = 产品号`） | `tb_prod_rel_screen`（画面组件） | 组件 ↔ screen 一一对应 |
| 元件（组件 `c_elements_json` 里的 elements） | `tb_prod_screen_rel_elem` | 组件内元件 ↔ screen 的 elem 列表 |
| 页面级按钮（画布 JSON 的 `buttons`） | **需新建存储**（见第四节） | 见第四节 |

### 核心前提（已查证）

- 产品工厂每个产品**只有唯一的 `c_version` + `c_chnl_code`**（如 `01003 → v1 / CA01`），反向同步时从产品号可反查上下文。
- `c_screen_no` 全局唯一且产品专属，组件 `c_group_code` 直接就是 `c_screen_no`，无需额外映射表。

## 二、四个决策点的落地逻辑

### 1. 允许新增（画布新增组件 → 产品工厂新增 screen）

画布里拖入一个**新组件**（`refCode` 对应一个不存在的 `c_screen_no`）时：

1. 从画布 `c_canvas_code` 解析产品号 + contentType
2. 反查该产品的 `c_version` / `c_chnl_code`
3. 用组件 `c_group_code` 作为新 `c_screen_no`，插入 `tb_prod_rel_screen`
4. 把组件内元件批量插入 `tb_prod_screen_rel_elem`
5. 把组件属性插入 `tb_prod_screen_prop`

**关键**：新增组件的 `c_group_code`（即 `c_screen_no`）必须由画布系统生成一个**全局唯一**的值（延续现有雪花 ID 或数字编码），并保证不与产品工厂已有 screen 冲突。

### 2. 删除不同步

画布里删除一个组件，**只从画布移除**（画布 JSON 的 items 不再包含该组件），**不删除**产品工厂的 `tb_prod_rel_screen` 对应记录。

原因：产品工厂 screen 可能被其他产品/渠道/模板引用，删除风险高，且「画布是产品页面的一个视图」而非产品工厂的编辑源。

### 3. 页面级按钮同步（需新建存储，见第四节）

### 4. 回写需「按钮 + 开关」双重控制

- 开关：`canvas.sync.enabled`（默认 `false`，关闭时任何回写都不执行）
- 按钮：在画布系统前端加「同步到产品工厂」按钮，点击后**显式触发一次回写**

**逻辑**：`canvas.sync.enabled = true` 且用户点击「同步」按钮，才执行回写；否则不执行。定时拉取（PULL）仍由开关控制，但**回写（PUSH）必须由按钮显式触发**。

## 三、反向同步的实现路径

### 触发点

`CanvasServiceImpl.saveCanvas` 现有钩子 `syncService.pushCanvas(canvasCode)` 已存在。改造为：

1. `saveCanvas` 时**不自动回写**（去掉或改为受控）
2. 新增接口 `syncService.pushCanvas(canvasCode)` 由**前端按钮显式调用**
3. 该接口内部先检查 `canvas.sync.enabled`，关闭则直接返回

### 回写核心逻辑（重写 `ProdCanvasSyncServiceImpl.pushCanvas`）

```
pushCanvas(canvasCode):
  1. 检查开关，关闭则 return
  2. 读画布 tb_canvas（含 c_canvas_json）
  3. 解析画布 JSON：items[]（组件列表）+ buttons[]（页面级按钮）
  4. 解析产品号 + contentType
  5. 反查 c_version / c_chnl_code
  6. 遍历 items 里的每个 component：
     - refCode = c_screen_no
     - 查 tb_prod_rel_screen 是否存在：
       - 存在 → 更新 screen 的元件/属性
       - 不存在 → 新增 screen + 元件 + 属性
  7. 回写页面级按钮（见第四节）
  8. 记录同步日志
```

### 关键数据流

画布 JSON 的 `items` 里，每个 component item 的 `refCode` 就是 `c_screen_no`，`childElements` 就是该 screen 的元件。所以反向同步时**不需要再查 tb_element_group 表**，直接从画布 JSON 解析即可（画布 JSON 已内嵌了组件和元件的完整信息）。

## 四、页面级按钮的存储方案（需额外决策）

### 现状

- 画布系统：页面级按钮存画布 JSON 的 `buttons` 数组，可增删改 ✅
- 产品工厂：页面级按钮是 **ftl 模板硬编码**，`fpic_prod_db` 里**没有**对应数据表（`tb_prod_screen_button` 只在历史库 `core_db` 里，且是测试数据）

### 问题

「页面级按钮同步到产品工厂」需要产品工厂**有一个存储位置**来接收这些按钮，否则无处同步。

### 三个候选方案

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 建新表** | 在 fpic_prod_db 建 `tb_prod_page_button`（c_prod_no + c_content_type 关联） | 结构清晰，产品工厂可读 | 需建表 + 产品工厂前端改造才能消费 |
| **B. 复用 screen_json** | 页面级按钮写入产品第一个画面的 `c_screen_json` 的 `headerButtons/footerButtons` | 不建表，融入现有结构 | 层级错位（页面级塞进画面级），语义混乱 |
| **C. 暂不同步页面级按钮** | 页面级按钮只在画布系统本地生效 | 零风险 | 不满足你的需求 |

### 推荐：方案 A（建新表）

建议在 fpic_prod_db 新建表：

```sql
CREATE TABLE tb_prod_page_button (
    c_pk_id         VARCHAR(50)  NOT NULL COMMENT '主键',
    c_prod_no        VARCHAR(5)   NOT NULL COMMENT '产品代码',
    c_content_type   VARCHAR(3)   NOT NULL COMMENT '画面类型: 1投保 2报价',
    c_button_no      VARCHAR(30)  NOT NULL COMMENT '按钮代码',
    c_button_name    VARCHAR(200) NOT NULL COMMENT '按钮名称',
    c_event_code     VARCHAR(200) COMMENT '事件代码',
    c_event_type     VARCHAR(30)  COMMENT '事件类型',
    n_show_order     INT          NOT NULL DEFAULT 0 COMMENT '显示顺序',
    c_crtr_code      VARCHAR(30),
    d_crtr_time      VARCHAR(25),
    c_uptr_code      VARCHAR(30),
    d_uptr_time      VARCHAR(25),
    PRIMARY KEY (c_pk_id),
    UNIQUE KEY uk_prod_content_button (c_prod_no, c_content_type, c_button_no)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='产品页面级按钮表';
```

**注意**：这个表建好后，产品工厂**前端**（ftl 模板）还需要改造为「从这张表读按钮」替代硬编码，才能让页面级按钮真正生效。这一步属于产品工厂侧改造，不在画布系统范围内，但需要你在方案里知晓。

## 五、已确认的决策

1. **页面级按钮同步**：暂缓（方案 C），先做组件/画布反向同步
2. **新增组件 `c_screen_no` 生成规则**：产品号 + 序号可读编码（如 `01003` + 3位序号）
3. **同步按钮位置**：画布管理页（CanvasBrowser），「发布记录、打开、复制」按钮旁，手动点击同步
4. **定时同步**：增加定时回写机制，用开关管理 + 可设置同步频率

## 六、实现方案（已确认）

### 触发方式
- 手动：画布管理页「同步」按钮 → 调后端同步接口
- 定时：`@Scheduled` 定时回写，`canvas.sync.enabled` 开关 + `canvas.sync.push-interval-ms` 频率
- 移除 `saveCanvas` 里的自动回写（改为仅按钮/定时触发）

### 反向同步核心逻辑
1. 解析 `c_canvas_code`（`01003_1`）→ 产品号 + contentType
2. 读画布 JSON，解析 items（component 列表）
3. 反查产品 c_version/c_chnl_code
4. 遍历 items：refCode 存在 → 更新 screen+元件；不存在 → 生成新 c_screen_no（产品号+序号）新增
5. 页面级按钮暂缓
